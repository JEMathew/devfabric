# Product Capabilities

The interactive Journey & Friction Explorer contains the stage-level map for all eleven developer stages and eleven agent stages. Technology examples there describe possible implementations. The prototype simulates the capabilities with local fixtures.

## Implementation boundaries

| Classification | Capabilities | What the user can verify |
| --- | --- | --- |
| Implemented local workflow | Five business case rehearsals, isolated tours, template search, catalog and team onboarding, request decisions, readiness repair, publication, scoped grants, evaluation, review and task metrics. | Explicit actions change browser records. A case reference can cross into a workspace without transferring approval, permission or results. |
| Simulated external operation | Infrastructure allocation, build and staging operations, invoice tool response and reminder delivery. | The environment, gate, receipt or outbox entry is a synthetic result. No provider account or customer endpoint is contacted. |
| Future capability simulation | Enterprise Context Graph in the gallery, service catalog and tool registry. | A shared read-only model explains local records and illustrative dependencies. Selecting a node or simulating an impact creates no grant, invocation or operational record. |
| Long-term product vision | Live enterprise context, cross-team orchestration, trusted execution and continuous intelligence. | The vision film and roadmap describe a direction. Identity federation, durable tenant state and real infrastructure adapters belong to a future pilot. |

## Problems and evidence

| Problem and root cause | Platform capability | Inspect in the product | Evidence or KPI |
|---|---|---|---|
| Engineers repeat discovery across scattered documentation because ownership and operation contracts are unclear. | Owned, searchable service contracts. | Developer Workspace → Service Catalog | Contract owner, operation, scope and response sample. Target discovery time. |
| A new service starts with repeated setup because teams lack an approved baseline. | Golden paths and service generation. | Golden Paths → Developer Studio | Generated catalog record linked to its template. Target time to first service. |
| Developers wait on environment and infrastructure handoffs because resources have separate request paths. | Self-service requests and environments. | Development Environments, Infrastructure Self-Service | Simulated resource state. Target request-to-ready time. |
| A release can advance with incomplete evidence when checks and promotions are disconnected. | Pipeline checks and guarded staging promotion. | CI/CD Pipelines → Testing & Quality Gates → Deployments | Build, test, security and promotion status for the service. Target passing change rate. |
| Agents cannot safely reuse services when tool descriptors or grants are missing. | Versioned contracts, tool registry and scoped identity. | Tool & MCP Registry → Agent Studio → Agent Identity | Tool, scope and invocation decision in the trace. Target authorized completion rate. |
| Reminder workflows can act on stale or unsuitable invoices because settlement, consent and history live in separate records. | Deterministic eligibility and replay suppression. | Workflow Orchestration → Execution Traces | Invoice-specific disposition. Target duplicate reminders per eligible invoice. |
| A sensitive notification lacks accountable review because delivery is coupled to draft generation. | Policy-controlled pause, review and resume. | Human Approvals → Audit Logs | Reviewer disposition and simulated outbox result. Target review wait and rejection rate. |
| Operators cannot diagnose a failure when decisions and effects lack a shared record. | Event traces, audit and recovery controls. | Agent Observability, Reliability & Recovery | Block reason and subsequent run evidence. Target recovery latency. |
| Platform investment is hard to prioritize when usage, assumptions and outcomes are mixed together. | Capability prioritization, adoption and economic modeling. | Product Insights → Platform Adoption, Business ROI, Prioritization | Local counters and labeled assumptions. Target adoption of approved workflows. |

The five cases cover invoice payment reminders, receipt scanning, bank reconciliation, tax document processing and payroll processing. The invoice workflow connects the operational workspaces. [Developer journey](developer-journey.md) · [Agent journey](agent-journey.md)
